# 豆包商品图片批量改图设计

日期：2026-10-04。用户已确认独立工具流程，测试使用“图片示例”中原有五张 Snipaste 商品图片。最新纠正：主要目标为图片文字转繁体，排版背景调整是次要功能。

## 目标与界面

Windows 10/11 64 位独立便携工具：选择本机 JPG/PNG/WebP 图片、填写输出文件夹、编辑改图要求，串行使用豆包网页版把图片内简体文字转为通用繁体。默认保留商品本体、背景、配色和排版；提供“同时换背景”和“同时调整文字配色与排版”两个默认关闭的选项。任何模式都保留文案、数字、单位和含义，不新增卖点。每次最多 20 张，总大小不超过 80MB。原图不覆盖，结果按原文件名保存为新 PNG，重名自动编号。界面显示当前图片、上传/生成/保存阶段、进度及原图结果对比，支持停止、继续、失败重试和已完成图片单张重做。默认提示词要求直接输出修改后的图片，强调繁体转换为第一目标，不仅给出建议。

## 方案

采用 Python 本地服务及操作页，专用可见 Chrome 浏览器通过标准 Playwright 操作网页。程序只使用正常上传、输入、发送、预览和下载入口，不调用豆包未公开接口，不复制已有浏览器会话，不隐藏自动化或绕过验证码。需已安装 Chrome，不附带大模型或另一个浏览器。登录由用户在专用窗口完成一次；该窗口的配置保存在本机用户目录，不随便携包分发，和 Codex 侧边栏登录独立。

此前本地 OCR 工具保留，新工具放在独立 doubao-image-tool 目录。现有 Chrome 商品采集插件不改动。

## 组件和数据流

输入校验和本机文件保存复用原工具的约束思路；队列持有输入临时副本和任务状态；浏览器适配器专职上传、发送及结果定位；网页只读取任务与已知图片预览。单个浏览器工作线程拥有全部浏览器对象，避免跨线程调用。

每张上传前记录已有助手生成图片标识，确保文件上传完成后发送一次提示词。只接受本次发送后出现的新助手图片，不能把原图预览、历史生成图片或缩略图当作结果。打开本次图片预览，优先网站下载入口；必要时保存页面实际展示的高清资源，不能猜测或修改签名 URL。下载后验证图片可解码且具有有效尺寸，再保存新文件及 JSON 记录（原名称、提示词、时间、状态）；不记录 cookies、token 或签名图片链接。

## 中断与恢复

用户点击停止后不再提交下一张，已发送的任务保留等待状态，可继续等待同一结果，避免重复发送。生成超过 8 分钟、登录失效、验证或配额提示、找不到控件、上传失败、下载失败均暂停，并提供具体阶段及重试/继续入口。不得因等待超时自动重复提交生成请求。用户明确重试单张时才允许再次发送。完成及失败项目保留；关闭工具保存任务元数据，但已经发出的未完成生成在重启后要求用户检查后明确重试，不宣称跨重启无缝恢复。

## 本地访问与保存

服务只监听 127.0.0.1，使用随机端口和请求 token，校验 Host/Origin，图片预览按任务索引定位，不提供任意文件读取接口。输入、输出路径指向运行工具的电脑，文件校验和原文件保护必须覆盖大小、格式、非法名称、重复名称、写入失败。登录配置不打包、不推送 Git。上传会把所选图片发送到豆包，使用账号自身免费额度，不承诺无限免费。

## 验证与交付

用当前已登录的豆包网页测试五张原图的上传、生成、高清获取及对应关系，保存原图/结果和对比页面。代码测试覆盖队列暂停继续不重复提交、错误恢复、不同图片结果映射、非法输入和保存冲突；适配器以页面结构样本测试历史图片过滤和高清选择。独立工具窗口登录后的真实端到端验收由用户完成，验证报告明确区分侧边栏实测、自动化测试与尚未验证项。便携包包含程序、运行依赖、中文说明和许可文件，不包含登录信息或用户图片。

## 已验证的页面信号

- upload_file_button → 上传文件或图片 → 文件选择；contenteditable 编辑框；chat_input_send_button。
- 助手生成图片 mdbox_image；预览关闭 canvas_close_btn。
- 预览中的已加载高清图片和聊天缩略图不同，不能直接保存聊天缩略图。
- 侧边栏中 edit_image_download_button 点击未收到下载事件，使用页面已展示高清图片下载成功。
