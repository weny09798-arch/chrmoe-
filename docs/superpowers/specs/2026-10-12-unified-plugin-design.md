# 采集与图片转换统一插件入口设计

日期：2026-10-12。基线：1.6.5（b148403）。

## 已确认目标

用户确认客户可以首次安装一次 Windows 后台组件，之后只操作 Chrome 插件，保留现有豆包、阿里云与 OSS 流程，不再手动启动图片工具或复制连接码。本次不恢复已取消的 Google/GPT 接入，不合并月度授权版本。

## 方案比较与选择

1. 推荐：Chrome Native Messaging 负责启动和发现后台，现有受保护的本机 HTTP 通道负责任务、配置、图片预览。复用已验证的队列、恢复和上传代码，变动集中在连接、配置界面及安装。
2. 全部改为 Native Messaging：需要重写任务通信与图片传输；图片消息受大小限制，对统一入口没有额外收益。
3. 完全纯插件：需要重写豆包自动化、付费接口与密钥保护，不能直接保留现有 Windows 加密保存。本次不采用。

官方依据：[Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)。它允许 Chrome 启动已登记的本机程序，Windows 安装时需要登记主机清单及允许的插件 ID。

## 客户操作

- 首次：加载插件，在插件页面点击“复制插件编号”，运行交付包内“安装后台组件”，粘贴编号，安装到当前 Windows 用户目录。不要求管理员权限，不安装 Windows 系统服务、不设置开机启动。后续只点击 Chrome 插件。
- 插件管理页自动连接后台，显示“正在启动／已连接／未安装／启动失败”，提供重新连接和安装说明。
- 同一页面提供采集、图片分类及数量限制、商品与包装文字开关、豆包免费／阿里云付费转换、结果预览和商品 Excel 导出。
- 同一页面的“图片服务设置”管理阿里云和 OSS 配置，支持保存、删除、状态及 OSS 上传和公开读取检查。保存密钥本身不发起翻译；OSS 检查可能产生少量请求和存储费用，按钮旁明确说明。
- 豆包的登录与验证码仍在专用 Chrome 页面由客户处理。插件提供“打开豆包／处理验证”，不将豆包网页嵌入插件，不承诺完全无人干预。
- 不自动在采集结束后开始转换，用户仍需点击开始；阿里云沿用付费费用确认。

## 安装与插件身份

- 不改变现有插件的 manifest key 或人为重建插件 ID，避免升级导致现有 Chrome 采集任务和替换链接看起来丢失。升级覆盖原插件目录后重新加载。
- 安装程序只接受合法的 32 位插件 ID，生成精确 allowed_origins，并登记当前用户的 Chrome NativeMessagingHosts。拒绝通配来源。
- 插件编号仅用于首次安装登记，不是密钥或日常连接码。移动插件目录导致 ID 变化时，页面提示重新登记，不放宽来源校验。
- 重复安装更新同一个固定后台目录和登记，不新增整套版本目录。安装前让已有后台安全停止，避免覆盖正在运行的文件；失败保留原可用组件。
- 卸载只移除本组件登记和程序，默认保留用户配置、豆包登录及恢复记录；不删除已上传的 OSS 对象或已保存商品任务。

## 启动和通信

- 插件后台脚本连接固定主机名，Native Messaging 主机仅接受明确的启动／状态协议及登记来源，不能传入任意命令、可执行文件路径或任意文件操作。
- 主机启动现有图片服务的新自动模式，隐藏终端，不打开独立工具管理页。仅监听 127.0.0.1 随机端口，保留随机凭证、实例锁、插件配对和接口来源检查。
- 启动结果通过原生消息返回地址与短期凭证，插件自动配对。凭证仅留在内存或当前浏览器会话，服务重启后重新获取；不写入商品任务、明文日志或安装包。
- 后台就绪描述由服务原子写入当前用户目录并加密保护，主机读取后必须验证实例确实可用；过期描述或占用锁不能被当作成功连接。并发打开只启动一个后台实例。
- 原生通道仅发送小型启动和状态消息，图片预览沿用 HTTP Blob，不把 Base64 大图放入原生消息。
- 自动启动不打开豆包、不上传测试图、不发起任何生成。旧后台不支持自动模式时提示更新，不静默退回手动配对流程。

## 配置保护

- 新增已配对插件专用的配置接口，允许阿里云凭证和 OSS 配置的保存、删除、读取脱敏状态、OSS 检查。未知字段、来源和操作明确拒绝。
- AccessKey 可以从插件设置表单输入，但不存入 Chrome storage、商品数据、日志、导出文件或客户包；保存后清空输入框，后端继续使用当前 Windows 用户 DPAPI 加密保存。
- 状态只返回是否配置、Bucket、地域和凭证来源等必要信息，不回传 Secret。OSS 继续支持复用翻译凭证或独立凭证。
- 复用原有用户数据目录，不迁移或重置已经保存的配置和豆包登录。

## 生命周期和结果

- 后台未安装或不可用时，仅阻止图片转换和配置操作，商品采集、查看和已有 Excel 导出继续可用。
- 关闭管理页不清空商品任务、已经保存的替换链接或后台任务；再次打开自动恢复同一批状态，不重复付费提交。
- Chrome 退出或原生连接中断后给重连留出 30 秒宽限；持续断开后停止后续提交。已提交图片进入收尾模式，允许同一张图片继续取回、上传并保存记录，随后安全退出并保留可恢复任务；收尾总等待最多 10 分钟，超时保留恢复信息且不重新提交。下次打开需要用户手动继续。
- 自动模式退出不沿用旧独立工具“退出即清空状态”的默认行为。提供明确的“清空转换任务”操作，安全等待正在处理的步骤后清除临时记录和缓存，保留登录、凭证、OSS 对象和插件已保存链接。
- 手动点击停止维持现有语义，不新增生成请求；继续获取与重试上传复用已有结果，重新生成维持费用确认。清空或删除商品仍拒绝迟到结果写入新任务。
- 已上传且匿名核对成功的链接才替换商品 Excel，部分完成导出仍保留未完成位置原图。XLS/XLSX 模板、价格、规格和 SKU 行不变。
- 插件重新连接时先拉取持久的已完成对应记录，再更新当前采集任务；正常退出不会导致刚完成结果因插件未轮询而丢失。

## 验证

- 模拟首次安装、合法／非法插件编号、重复登记、当前用户安装／卸载、后台未安装、启动失败、旧后台、过期描述及多页面并发。
- 检查非登记来源不能启动或配置后台，密钥不回显、不入日志／Chrome storage，首次启动不生成图片或收费。
- 检查停止、关闭、断开、重连、后台重启和清空时不重复提交、不丢失已有结果、不将旧任务写回新任务。
- 回归豆包、阿里云、分类限量、包装开关、OSS 失败只重试上传、部分完成导出的 XLS/XLSX。
- 用隔离 Chrome 与临时用户数据目录验收实际原生通信、后台自动启动、插件设置、恢复和卸载；不修改用户正在运行的任务，不发起额外真实付费生成。
- 实际豆包登录或验证码由用户处理。OSS 账号不可用时交付模拟验证结果，并明确在线上传验收未完成。

## 交付

- 统一入口版本定为 1.6.6，不含 Google/GPT 或授权系统。
- 覆盖固定交付目录 D:\Desktop\chrome插件\交付包\商品采集与图片转换_1.6.1 和现有单一压缩包，历史目录名保留。
- 包含商品采集插件、后台组件安装／卸载入口、依赖及使用说明；客户无需打开旧独立图片工具页面。
- 源码和版本历史由 Git 保存，不新增整套交付文件夹。客户包不包含开发者密钥、用户配置、登录资料或测试图片。
