# 拼多多完整商品详情与 SKU 导出设计

## 目标

插件继续按商品名称搜索拼多多商品，按主图合并重复商品，并在同图商品中保留展示价最低的一条。每个商品名称最多保留 20 个商品。选品完成后，插件逐个读取这些商品的详情页，把拼多多实际提供的商品信息和全部 SKU 组合写入货憨憨的 22 列 Excel 模板。

插件不得用固定值或猜测值补充拼多多没有提供的数据。缺失字段保持空白，并在管理页显示详情采集是否完整。

## 采集流程

每个商品名称分为两个连续阶段：

1. 搜索选品阶段
   - 读取搜索结果卡片的标题、主图、展示价格、商品 ID 和详情链接。
   - 按主图相似度去重。
   - 同一主图组保留展示价最低的商品。
   - 保留满 20 个主图组后立即停止继续滚动和扫描。
2. 详情补全阶段
   - 使用独立的非活动标签页逐个打开已选商品，避免改变搜索结果页。
   - 等待商品详情页加载完成后读取详情数据。
   - 每次只处理一个详情页，减少触发拼多多访问限制的概率。
   - 完成或记录失败后关闭详情页，再处理下一个商品。
   - 当前商品名称的详情补全结束后，进入下一个商品名称。

管理页进度显示当前阶段，例如“搜索商品 16/20”或“补全详情 7/20”。已经取得的基础信息会持续保存；详情采集中断后可以从未完成的商品继续。

## 详情数据模型

每个选中的商品在原有基础字段上增加：

- `galleryImages`：商品主图列表。
- `descriptionText`：详情页可读取的纯文本描述。
- `detailImages`：详情图列表。
- `category`：页面明确提供的商品类目。
- `attributes`：品牌、产地、材质、型号等键值属性。
- `videoUrl`：页面明确提供的视频地址。
- `certificateImages`：明确标记为证书的图片。
- `sizeChartImages`：明确标记为尺码表或尺寸图的图片。
- `specNames`：最多两个规格名称。
- `skus`：SKU 数组，每项包含规格值、平台 SKU、售价、SKU 图片、库存、重量和尺寸。
- `detailStatus`：`pending`、`running`、`done`、`partial` 或 `error`。
- `detailNote`：缺失、受限或解析失败的简短原因。

详情页只有一个售价且没有可识别 SKU 时，生成一个默认 SKU，并使用详情页售价；详情页售价无法读取时，回退到搜索结果中已经确认的展示价。不得生成虚假的规格名称或规格值。

## Excel 字段映射

| 模板列 | 数据来源与规则 |
| --- | --- |
| 产品主编号 | `PDD` 加拼多多商品 ID；同一商品的全部 SKU 使用同一编号 |
| 产品名称 | 详情页标题；缺失时使用已验证的搜索结果标题 |
| 货币类型 | `CNY` |
| 产品主图 | 全部主图 URL，使用中文逗号分隔 |
| 货源链接 | 规范化的拼多多商品详情链接 |
| 货源平台 | `拼多多` |
| 货源ID | 拼多多商品 ID |
| 详情描述 | 详情页纯文本描述 |
| 详情图 | 全部详情图 URL，使用中文逗号分隔 |
| 货源类目 | 仅填写页面明确提供的类目 |
| 自定义属性 | `名称:值`，多个属性使用中文分号分隔 |
| 产品视频 | 页面明确提供的视频 URL |
| 产品证书 | 明确识别为证书的图片 URL |
| 尺寸图表 | 明确识别为尺码表或尺寸图的图片 URL |
| SKU规格1 | 第一规格值 |
| SKU规格2 | 第二规格值 |
| 平台SKU | 页面提供的 SKU ID 或编码 |
| SKU售价 | 该 SKU 的实际售价；没有 SKU 时使用确认的商品价格 |
| SKU图片 | 对应规格或 SKU 图片 |
| SKU库存 | 页面明确提供的库存数量 |
| SKU重量(KG) | 页面明确提供的重量；没有则留空 |
| SKU尺寸(CM) | 页面明确提供的长宽高；没有则留空 |

模板中的示例文字只用于说明格式，不能作为商品数据写入导出文件。

## 多 SKU 行规则

一个商品有多个 SKU 时，一个 SKU 输出一行。第一行填写全部商品公共字段和该 SKU 字段；后续行只填写相同的产品主编号以及该行对应的 SKU 字段，商品公共字段留空，保持与模板示例一致。

如果详情页提供两个规格维度，按页面实际存在的 SKU 组合输出，不自行计算不存在的笛卡尔组合。相同 SKU ID 不重复输出。

## 页面解析与兼容

详情读取器优先读取页面公开呈现的 DOM 数据，并可读取页面自身内嵌的商品状态数据。解析器只接受当前商品 ID 对应的数据，并对图片 URL、SKU ID、价格和库存进行类型检查。页面结构无法识别时保留基础商品数据，将详情状态标记为失败或部分完成，不影响其他商品继续采集。

详情采集标签页如果进入登录、验证码或访问频繁页面，任务暂停并保留进度。用户处理后继续时，从当前商品重新读取，不重新搜索已经完成的名称。

## 存储与恢复

详情字段保存在现有任务数据中。旧版本保存的任务在恢复时，为已有候选商品补上待处理的详情状态，不丢弃原有搜索结果。清空按钮继续清除商品名称、搜索结果、详情数据和进度。

为避免 Chrome 本地存储超限，保存前对 URL 列表去重，并限制明显重复或无效的图片地址。若完整详情仍超过存储限制，管理页显示明确错误并保留内存中的可导出结果。

## 测试与验收

实现前先增加失败测试，再修改代码。测试至少覆盖：

- 详情页数据解析为主图、详情图、属性、视频、两个规格维度和实际 SKU 组合。
- 同一商品的多 SKU 行共享同一个产品主编号。
- 第一 SKU 行含公共字段，后续 SKU 行不重复公共字段。
- 没有重量、尺寸、证书等字段时保持空白。
- 没有 SKU 的商品仍输出一行且价格有效。
- 详情采集失败不会丢失基础链接，也不会阻止后续商品。
- 20 个主图组选满后不再扫描搜索结果。
- 旧任务恢复、暂停继续、清空和导出仍然正常。
- 导出的 `.xls` 保留原模板的 22 列、表头、样式、合并区域和列宽。

最终用真实拼多多详情页做一次只读采集验证，并生成测试 Excel。检查一个含多规格商品和一个缺少部分字段的商品，确认货憨憨能够识别产品和 SKU 行。

## 限制

拼多多可能针对不同账号、地区或活动展示不同价格和库存，插件只能保存采集当时页面提供的数据。登录验证、验证码和平台访问限制不能绕过。拼多多没有展示的重量、尺寸、证书、类目或视频必须留空。
