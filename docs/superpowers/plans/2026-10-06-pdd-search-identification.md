# 拼多多搜索名称和链接识别修复

沿用用户批准的搜索页保留方案，仅修复名称与已加载数据读取，禁止恢复点击商品取地址或额外搜索接口。

证据：用户 Chrome 当前“牙刷”搜索页有 40 条卡片，插件跳过名称 23、链接 17。实际标题 div 同时含直系文字、图片、图标 span，旧 titleFor 只查叶子节点，遗漏有装饰的标题。卡片只有 data-uniqid（列表位置，绝不是商品 ID），没有真实链接。当前官方搜索脚本使用 React 组件的商品 data；页面脚本没有内嵌商品列表，仅读 rawData 不足。官方 vendors 脚本使用 __reactFiber$、__reactProps$。

1. 用实际卡片结构构建测试，修复从标题容器读取文字，过滤图标和营销标签，不收集父容器整页文案。
2. 测试无 rawData 时从可见卡片 DOM 对应的 React 已提交 props 读取商品记录，限深、限量，仅读 data/goods/item 等商品字段，不读取账号、store、context，不调用事件、不读取网络。
3. 仍使用标题和图片的唯一匹配；多个真实 ID 时拒绝。绝不使用 data-uniqid 当 ID。保留 DOM 真实链接优先、阻断停止和 3 秒间隔。
4. 补查分页后 React 更新、隐藏节点、旧 alternate、缺字段、重复图片和错误标题、外站等边界。执行完整测试和脚本检查，只读审查后更新 1.5.9、镜像、Git 和无说明文档客户包。

Chrome 检查工具的只读 DOM 快照不能证明内存中的组件字段值。应在安装扩展后对当前页面读取确认，不能以模拟数据测试替代实页验证或宣称真实采集成功。

实际组件证据：goodsData.goodsID=910957227286，goodsName 的品牌带【】，imgUrl 是主图 URL；旧读取器漏掉 imgUrl，严格标题关联也未兼容品牌括号。已按证据增加两个先失败再通过的回归测试。另加共享 return 和复用 child 的 React 更新回归，按当前父组件 child 成员读取已提交数据。

验证完成：用户手动运行更新后的只读检查，当前搜索页 40 张卡片、33 条 identified、6 条 unnamed，blocked=false；66 个组件记录含重复数据，最终按唯一 ID 匹配。没有打开商品、重新搜索、滚动或请求额外接口。完整 309 项测试及 npm run check 通过，独立代码复查无剩余重要问题。尚未验证安装更新后的完整详情批次。
