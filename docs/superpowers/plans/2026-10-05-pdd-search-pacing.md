# 拼多多搜索页保留与采集间隔

用户批准方案，2026-10-05；后续明确当前搜索仍受限，先完成代码和本地测试，不访问拼多多试采。

## 实现

1. 禁止拼多多点击缺链接卡片。读取已有 DOM 链接、ID，或从页面 rawData 中提取商品 ID、标题、图地址；标题和主图须唯一匹配，来源网址和关键词须一致。没有匹配、多个 ID、非安全整数均跳过。只读取已有数据，无新增接口请求。
2. 同一关键词复用搜索标签和滚动位置。删除补齐保留已扫描计数、seen、排除名单、已采详情；保留 200 条扫描总量。手动重新搜索可清零重载，其他平台原有补齐逻辑不变。
3. 完整详情仍在独立标签页逐件读取，每件拼多多详情结束后（包含普通失败）设置 task.pddNextActionAt 为当前时间加 3000 毫秒。下一件、下一关键词开始前按剩余时间等待，最多每 250 毫秒检查暂停、停止。清空复用停止流程；恢复序列化任务保留截止时间，旧任务无字段不等待。
4. 管理页显示等待提示。访问频繁、登录和验证仍走阻断流程，保留对应页面和结果，无自动刷新或重试。SKU 稳定检查不变。
5. 版本 1.5.8，镜像目录同步。完成回归、审查后保存 Git，并整理仅含扩展运行源码及第三方许可证的客户 ZIP。

## 验证范围

- 真实内容脚本在受控 DOM 中读取卡片；浏览器通信串联 MAIN 页面数据读取和隔离内容脚本，核对来源、唯一匹配、现价、滚动位置、不点击和阻断后不额外读取。
- Runner 虚拟时钟核对成功/普通失败后 3 秒、跨关键词间隔、暂停/停止、恢复剩余等待；管理页受控 DOM 验证等待提示和清空期间不开始下一件。
- 数量目标、200 上限、不足提示、删除排除与原详情保留；淘宝、1688、SKU、Excel 的现有全套回归。
- 运行 npm test、npm run check、git diff --check；源码镜像与客户包逐文件验证。
- 在线试采待用户确认手动搜索恢复后进行。本地测试不能证明所有实际拼多多页面适配成功，也不能保证解除限制或避免平台检测。
