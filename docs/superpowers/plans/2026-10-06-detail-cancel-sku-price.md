# 删除正在采集的商品与拼多多限时 SKU 价格修复

目标：删除后不再执行这个商品的后续详情操作，仍保留排除名单与自动补齐；正确读取限时主价格，避免每规格无效重试约 24 秒。

证据：manager 删除后仅调用 Runner.pauseForRefill；Runner 的 enrich 未传递取消条件，browser 的页面操作与等待不检查暂停或删除。当前 Chrome 商品 1010242122937 的 .ujEqGzEB 主价格节点是 role=img、aria-label="仅55分钟¥37.1"，原 anchored 正则不接受该前缀。

1. tests/products.test.mjs 复现删除正在采集及队列后续商品。Runner.enrich 给 ports.enrich 第三个参数 cancelled(): boolean，依赖当前 intent 和 selected(job) 对象成员。开始前与结果返回后再次确认成员；取消后仍在队列的商品回到 pending，删除对象不写回、不标记失败，继续按排除名单补齐。取消已开始的 PDD 商品仍执行 3 秒商品间隔。
2. tests/browser.test.mjs 复现等待期间取消、MAIN 读完后取消、创建期间取消、限制响应与取消并发。browser.enrich(item, task, cancelled) 在每个页面操作之间检查，等待分成最多 100 毫秒片段；已派发的 Chrome 调用完成后检查，不再派发下一步，finally 关闭详情标签页；限制提示优先保留页面并暂停。
3. tests/detail-content.test.mjs 使用实际限时标签复现；主价格 regex 增加 `仅\d+分钟` 等时间前缀，但不接受券前金额、折扣、区间。保持选中、价格和图片三次稳定及 2.4/4.8/8.4 秒保护等待，不改成短延迟冒险读取。验证价格、图片延迟与缺货回归。
4. 完整测试、check、独立只读代码复查；更新版本 1.5.10 和两个插件目录，保存 Git，打包 31 个运行文件且无说明文档。真实页面仅做只读结构确认，不在用户正在采集的标签页中操作规格或下单。

验证：删除当前详情、删除已快照的后续对象、删除其他对象仍保留当前详情；取消发生在创建、MAIN 读取、启动等待和 SKU 轮询等待；与验证响应并发仍保留阻断页面。真实限时价格标签及三款更新场景正常读取，拒绝券前、区间与多个金额。320 项完整测试通过，npm run check 通过，独立复查 115 项专项测试通过且无重要问题。未操作用户当前商品规格，实际速度仍需升级后重采确认。
