# Monthly licensing 1.7.0 implementation

## Global Constraints

- One code binds one Windows computer; first activation starts exactly 30 days. Renew adds 30 days from max(now, expiry). Owner follows the same rules. Unbind does not reset expiry.
- Expiration/disable/unbind stops new collection and new generation, but existing results remain viewable/exportable. Already submitted images may be retrieved, uploaded and persisted before pausing. Renewal never automatically restarts work.
- Verify at startup, before starting work, and every 5 minutes. Signed offline allowance is at most 24 hours after successful online validation and never beyond expiry. Explicit denial invalidates cached permission; clock rollback requires online validation.
- Ed25519 signed credentials; hardware digest derived from Windows MachineGuid and system volume ID. No random fallback. DPAPI protects license code/cache. Never ship private keys, passwords, databases, personal credentials or a production bypass.
- No server/domain is available. Use isolated fake services and simulated conversion/OSS, no real paid requests. Do not overwrite the usable 1.6.4 delivery directory/ZIP or its profile/state. Formal customer package and real two-computer acceptance are deferred until deployment.
- Preserve existing type limits, image ordering, SKU mapping, OSS verification and original/partial XLS/XLSX export behavior. Existing unlicensed editions cannot be retroactively disabled.

## Contract and architecture

Separate `license-server/` Flask app, SQLite transactions, Ed25519 signer, admin templates, Docker/Gunicorn/Caddy deployment. Separate focused client modules under `doubao-image-tool/` for hardware, transport/trust/cache and build configuration. Client contains only server HTTPS URL/public key. Development defaults are unconfigured/locked; loopback HTTP is allowed only through explicit injected test configuration, never a shipping environment bypass.

Protocol POST `/v1/activate` and `/v1/validate`: JSON code, device_hash, nonce. Responses contain status, server_time, expires_at and signed credential envelope; positive signed JSON payload includes protocol version, license_id, device_hash, issued_at, expires_at, lease_until <= min(issued_at+86400,expires_at), request nonce. Canonical UTF-8 sorted compact JSON; envelope payload base64url bytes plus Ed25519 signature base64url. Client verifies nonce for live responses and device/expiry/lease on cached responses. Server stores SHA256 of high-entropy code, never plaintext (plaintext displayed once at creation). Successful activation/validation serialized with SQLite BEGIN IMMEDIATE for binding races. Disabled/unbound/device mismatch/expired are explicit denied statuses; rate limits shared in SQLite across workers.

Native `LicenseAuthority` interface: `activate(code)`, `status(force_refresh=False)`, `require_new_work(force_refresh=True)` raising a specific licensing exception. Status public JSON: allowed, status, message, expires_at, remaining_days, offline, checked_at. Authority protects cache independently from transient queue state. Injection of authority in tests is explicit; production app always creates real configured authority. API code/cache never exposed through status or logs. Existing local pairing/token controls protect license bridge APIs.
