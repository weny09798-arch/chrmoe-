## 授权与 RAM 独立

授权服务器使用独立的 `license-server/` Flask 服务与 SQLite 数据库。授权码只控制软件使用期限与单机绑定，不需要 RAM、OSS、翻译服务账户或任何 AccessKey。所有者通过 HTTPS 管理后台创建授权码并给自己的电脑按相同方式激活，没有永久或超级管理员客户端免授权。客户使用收费翻译、OSS 时，自己再配置相应云服务凭证。

一枚高熵授权码的明文仅创建时显示一次，数据库仅保存 SHA256。首次激活后到期为 `now + 2592000`；续费为 `max(now, expiry) + 2592000`；解绑保留到期日期。签名采用 Ed25519/RFC8032，客户仅持有公开验证密钥；实现参考 [PyCryptodome 官方 EdDSA 文档](https://www.pycryptodome.org/src/signature/eddsa)。

## 未来正式服务器部署

以下 Linux 命令须在取得服务器、域名后由所有者执行，示例域名必须替换为实际域名。本次没有执行这些命令。

1. 取得 Linux 主机和实际域名，将 A/AAAA 指向服务器；开放外部 80/443，其他应用端口不对公网开放。校准服务器时间。Caddy 证书数据必须可写并持久保存。[Caddy 官方自动 HTTPS 条件](https://caddyserver.com/docs/automatic-https)说明了 DNS、端口和数据目录要求。
2. 将服务源码单独部署到如 `/opt/monthly-license/license-server`；客户包不包含此目录。建立独立 Python 环境，安装 `license-server/requirements.txt`。Flask 生产运行需使用专用 WSGI 服务器，本方案为 Gunicorn，禁止用开发服务器代替。[Flask 官方生产部署说明](https://flask.palletsprojects.com/en/stable/deploying/)。
3. 从服务器源码目录初始化外部私有目录：

```sh
python -m licensing.cli /srv/monthly-license-private --origin https://实际授权域名 --container
```

密码通过隐藏提示输入，至少 16 字符；不要放进命令参数、环境或截图。初始化拒绝已有目录及仓库内路径，生成随机 Ed25519 私钥、会话密钥、scrypt 管理员密码哈希。记录输出的 base64url raw32 公钥，确认与私钥匹配并另存公开配置。服务目录之外的 `/srv/monthly-license-private` 包含 `config.json`、`signing.pem`、`data/`，只允许服务账户与管理员访问（POSIX 目录 700、文件 600）。容器使用 UID/GID 10001，配置和私钥只读挂载，数据库目录可写；设置相应所有权。Windows 测试私有目录还需使用 ACL，不能依赖 POSIX mode。

4. 配置服务环境并先检查 Compose：

```sh
export LICENSE_PRIVATE_DIR=/srv/monthly-license-private
export LICENSE_HOST=实际授权域名
docker compose config --quiet
docker compose up -d --build
```

`PUBLIC_ORIGIN` 必须与 `https://` 加域名完全一致。Compose 使用外部文件 bind mount；私钥与配置不经过镜像复制。Gunicorn 两 worker 只在内部网络开放 8000，Caddy 唯一代理，覆盖转发头。`TRUST_PROXY` 只用于应用不能被外部直接访问的此结构。持久化 `caddy_data`、`caddy_config`。如果不用 Docker，初始化时去掉 `--container`，通过 `LICENSE_CONFIG` 指向外部 config，在等效 HTTPS 代理后运行 Gunicorn；不得把 8000 暴露公网。

5. 浏览器访问实际域名 `/admin/login`，创建隔离验收授权码。检验成功激活、拒绝第二设备、续费、停用/恢复、解绑保留到期、重启后记录持久存在。确认日志只记录状态，不记录授权码、请求体、设备标识或密钥。

## 备份与恢复

备份外部 `config.json`、`signing.pem`、`data/` 中 SQLite 数据库；同时保存公开公钥、源码版本、依赖版本、域名和 Caddy 持久卷。管理员密码与软件授权码由所有者的密码管理器独立保存。备份加密、限制访问并离线保存第二份，永远不放客户包或源码仓库。

简单的维护备份流程：`docker compose stop app`，确认 app 已停止后，完整复制私有目录至受保护的备份位置，完成后 `docker compose start app`。使用 SQLite backup API 的在线一致性备份也可；禁止把运行中的数据库与 journal/WAL 分开拷贝。Caddy 数据使用其持久卷的完整快照备份；若工具不支持一致性卷快照，停 Caddy 后复制，完成后恢复启动。保留全部备份的访问权限。

恢复时先停 app，将一致备份恢复到原私有目录；保持原签名私钥、密码哈希、会话密钥及数据库。恢复 UID/GID 10001 与 700/600 权限，检查配置容器路径正确，再启动。先用已有测试授权验证：到期时间、设备绑定、停用状态未变化，原公钥能验证，已发授权码可继续使用。数据库不能凭记忆重新创建，否则会丢失期限与绑定。真实演练必须在隔离实例完成后再调整正式服务。

## 密码、私钥或数据库丢失

管理员忘记密码但仍可访问服务器：停 app，离线用 `werkzeug.security.generate_password_hash(getpass.getpass(...), method='scrypt:32768:8:1')` 生成新强哈希（新密码同样要求至少16字符、8种不同字符），原子替换外部配置的 `ADMIN_PASSWORD_HASH`，并用 `secrets.token_hex(32)` 更换 `SECRET_KEY` 注销旧会话。保留 `PRIVATE_KEY_PATH`、私钥、DATABASE 及全部授权记录，恢复权限，重启并验证。不得重新运行初始化覆盖私有目录，也不得直接编辑客户程序的授权逻辑。密码丢失与软件到期无关，不应重置授权日期。

签名私钥遗失：优先恢复加密备份中的同一私钥。没有备份时无法恢复旧签名能力；需要生成新私钥、公钥，保留原数据库期限/绑定，重新构建客户端公开信任配置并安排客户更新。旧客户端不信任新签名，旧离线凭证最多只能在原 24 小时/原到期内使用；不能靠修改到期或忽略验签兼容。私钥泄露按同样方式更换信任并停用旧服务密钥，提醒客户升级。

数据库遗失：恢复最近一致备份，再依据所有者账务记录核对最近续费、停用与解绑变更。无备份时无法可靠重建绑定/到期历史，先停止发放与续费，人工核对记录后恢复；不要批量重新首激活来变相赠送新期限。授权码明文遗失无法从 SHA256 数据库逆推出；优先查所有者密码管理器，不重新创建来重置期限。

## 固定公开配置与客户文件白名单

正式候选构建必须提供独立 JSON，仅有 `server_url`（实际 HTTPS origin，无账号、路径、query、fragment）和 `public_key`（Ed25519 raw32 的规范 base64url，共 43 字符）。缺少、HTTP、额外/private 配置或非规范 key 会在 PyInstaller 前失败。构建只修改隔离 staging 中的 `license_config.py`，不更改源默认锁定值；运行时不读取环境变量来替换域名/公钥。`LicenseBuildConfig(...allow_loopback_http=True)` 只存在于明确注入的测试，评估可执行包保持未配置锁定。

`doubao-image-tool/customer_build.py` 是文件白名单与扫描入口：客户仅有冻结运行依赖、工具运行源码、Web UI、插件列举文件、导入模板、使用文档和第三方许可。禁止复制 backend、server private key、DB、config/admin credentials、实际个人 DPAPI、浏览器 profile、state/cache、锁文件、tests 或测试 fake authority。`_internal/certifi/cacert.pem` 是 requests 的公共 CA 证书包，不是签名私钥；扫描仅允许这个明确位置并拒绝私钥内容。依赖库源码不做泛化文本凭证匹配，自己的 JSON/private PEM 与全部私有状态文件仍检查。扫描不能替代对输入源码和最终发布物的人工审查。

客户端直接依赖 cryptography、requests 已固定在 `doubao-image-tool/requirements.txt`，冻结导入与 `licenses/dependencies.json`、组件许可均须检查。服务独立使用 `license-server/requirements.txt` 和 Docker，不随客户包分发。
