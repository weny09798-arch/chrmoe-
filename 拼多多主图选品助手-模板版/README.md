# 拼多多 · 主图选品助手

逐个输入商品名称并点击“添加”，插件会立即在你已登录的拼多多、1688 或淘宝网页中搜索；后续名称自动排队。每个名称按商品 ID 去重，获得设定数量（默认 20）的链接后自动采集详情图片、SKU 等信息，再处理下一个名称，最后统一导出 Excel。缺搜索图片不会丢弃链接；不同 ID 的同图商品分别保留。若不足设定数量，最多扫描 200 条结果。

## 安装（无需编译）

1. 在平时登录拼多多的 **同一个 Chrome 配置**中，地址栏输入 `chrome://extensions`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本项目的 **extension 文件夹**，不要选择项目外层文件夹或 ZIP 文件。
4. 点击 Chrome 右上角扩展程序图标，将“拼多多 · 主图选品助手”固定到工具栏。
5. 点击插件图标，打开管理页。第一次建议只添加一个名称，验证搜索结果后再批量添加。

从旧版本升级后，请在 `chrome://extensions` 找到本插件并点击“刷新”，再重新打开管理页。

完整路径：`D:\Desktop\chrome插件\extension`

## 使用

1. 先在 Chrome 登录 `https://mobile.pinduoduo.com/`。
2. 在插件中输入商品名称，点击“添加”或回车便立即开始搜索；继续添加的名称进入队列。清单和采集结果会自动保存在本机，Excel 在最后点击“导出 Excel”统一下载。
3. 插件会新建专用采集标签页，复用同一 Chrome 中的登录状态。请保持管理页和采集页打开，电脑不要休眠。
4. 搜索无需读取图片像素或申请图片去重权限。采集到的第一张详情相册图片用于预览和导出；读不到图片时保留链接并标记详情不完整。
5. 通过“查看采集页”检查当前页面。出现验证码或需要登录时，插件会保留当前详情标签；由你在该页处理后，再回管理页点击继续，插件会从同一商品继续读取。
6. 进度条显示已处理商品名称的比例，下方实时显示搜索扫描或详情补全进度，并分别统计详情完整、部分和失败数量。展开商品链接明细可查看每件商品的详情状态及原因。搜索结束后，插件会逐个打开选中商品的详情页，读取页面实际提供的主图、详情图、属性、规格和 SKU 等信息；详情阶段可能比搜索阶段耗时更长。
7. 采集结果持续累积；选择“模板同款 .xls”或新版“.xlsx”，最后点击一次“导出 Excel”并在保存窗口选择位置。运行中、暂停、停止或部分失败时也可以导出已有结果。
8. 如需从头开始，点击“清空全部”；这会停止当前采集并删除本机保存的名称、进度和结果。已下载到电脑的 Excel 文件不会被删除。

## 图片选品与自动补齐

展开“查看已收集的商品链接”，每行显示该商品采集到的第一张主图；没有主图时使用搜索图，图片加载失败则显示“暂无图片”。点击行末的 × 可删除不想要的商品，导出的 Excel 也会移除它。

删除后约 1 秒自动补搜对应名称，连续删除会合并处理。正在采集时先等当前页面操作结束，再补齐这个名称原来设定的数量和价格范围；其他保留商品及其详情不变。只排除被删商品 ID，允许其他 ID 的同图商品。排除记录保存在本机，点击“清空全部”才会清除。旧版本保存的 ID 排除名单继续生效，但图片和指纹排除不再生效。

主动暂停、停止或出现登录、验证码提示时，自动补搜会暂停。处理提示后点击“继续”，或对已停止的名称点击“重新搜索”。每轮补搜最多检查 200 条新候选，达到数量即停止；搜索结束仍不足时显示实际数量和原因。

## 淘宝采集（1.4.0）

先在同一个 Chrome 中登录淘宝，将“采集网址”改成 `https://www.taobao.com/`，再输入商品名称并添加。插件会在淘宝搜索，使用数量、价格范围、ID 去重、详情图片预览、删除补齐和累计导出规则。搜索列表出现明确“下一页”时会继续翻页，达到设定数量即停止。天猫商品保留天猫详情链接，Excel 货源平台区分“淘宝”“天猫”。

淘宝详情读取页面提供的名称、主图、描述、详情图、类目、参数、视频、证书、尺寸图表及 SKU 规格、售价、图片、库存、重量、尺寸。按实际 SKU ID 匹配数据，并按商品声明的规格顺序填写两列规格；没有提供的数据留空。页面只显示基础信息、未加载完整规格或详情时标为“部分”，不会凭搜索价格虚构规格和库存。登录或验证提示需在“查看采集页”自行处理后继续。

升级后在 `chrome://extensions` 刷新插件并重新打开管理页。如果 Chrome 因新增淘宝网页权限而要求重新启用，请按页面提示启用。旧的结果和输入名称仍保存。模板格式不变；淘宝产品主编号使用 `TB` 加货源 ID，天猫使用 `TM` 加货源 ID，避免与其他平台重复。

本次淘宝接入通过受控搜索页面、初始化数据、SKU 映射、分页、详情等待、推荐隔离及 Excel 导出测试。开发浏览器安全策略阻止访问淘宝实站，因此尚未验证你的登录页面；实际页面版本不同或只提供部分数据时，需要根据试采结果继续适配。

导出的工作表按用户提供的“导入产品模板.xls”排列：名为“模版”，第 1–8 行保留字段说明，第 9 行是原样的 22 列表头，数据从第 10 行开始。旧版 `.xls` 还保留模板的列宽、Calibri 字体和必填表头的红色标记。会根据页面实际提供的数据填写产品主编号、产品名称、主图、货源信息、详情图、类目、自定义属性、视频、证书、尺寸图表、SKU 规格、售价、图片、库存、重量和尺寸；页面没有的数据保持空白。“详情描述”列保留但始终为空，图文详情只导出图片地址，旧结果重新导出也会去掉文本。一个商品有多个 SKU 时会导出为多行，这些行使用相同的产品主编号，重复的商品公共字段只填写在第一行。产品主编号使用对应的货源 ID，不会在每次导出时从 1 重新编号。来源链接可点击，价格和标题均按模板保存为文本。模板中的示例商品不会混入导出结果。当前任务状态、跳过原因和不足设定数量的情况在插件“采集结果”中查看。

## 商品 ID 去重的含义（1.5.0）

- 每个名称独立收集，不同名称之间允许相同链接。
- 同一个商品 ID 只保留一条；不同 ID 无论图片是否相同都分别保留。已取消图片相似度分组及同图最低价规则。
- 按发现顺序保留设定数量的 ID，然后逐个自动打开后台详情页采集图片和其他字段。
- 不足设定数量时导出实际数量，最多扫描 200 条或在页面明确提示结束时提前结束。
- 价格区间、“起”价或无法明确区分售价的卡片仍会被跳过；没有搜索图片不跳过。详情失败保留链接，缺商品图片则显示部分详情及原因。
- “已缴纳保证金”“好评超98%同款”“1万+人好评”、地区不配送、“未发货秒退”和“本店已拼500万+”等平台标签不作为产品名称。商品标题至少要与输入的搜索名称共享一个字母或汉字；仅数字相同不够。无法识别真实商品名的卡片会被跳过，因此可能不足 20 条。
- 导出时也会过滤旧任务中明显不相关或属于平台标签的标题。已采集的旧结果可通过对应行的“重新搜索”重新补充；点击“清空全部”则从头开始。

## 中断与故障

- “暂停”会等当前页面操作结束，再保存进度；“继续”恢复未完成名称。
- 关闭管理页或浏览器不会清空商品清单。再次打开时，未完成任务恢复为暂停状态。
- 旧结果需要重采时，在“采集结果”对应行点击“重新搜索”；只替换该名称的旧结果，其他名称保留。
- 在专用采集页手动切换到其他商品或搜索词，可能触发暂停。请返回任务对应搜索页再继续。
- 插件遇到无直达链接的卡片时会打开商品详情页读取链接，然后明确返回当前名称的搜索页并恢复滚动位置；如平台导航异常导致任务暂停，可查看采集页的网址并反馈。
- 没有可靠结束标记但列表不再加载时，会显示加载停滞并保存已有结果，不把它当作正常结束。
- 页面结构变化或图片来源不受支持时，可能需要更新适配器。请保留报错文字和当前页面截图便于排查。
- 在货憨憨等第三方平台导入后，若商品图片、名称、价格和货源 ID 已显示，但状态为“采集失败”，表示表格已被读取，后续平台抓取货源商品的步骤仍可能失败。可用同一商品链接在该平台直接采集一次，以区分链接兼容性与平台采集故障；插件无法保证第三方平台的采集结果。

## 当前验证范围

已提供核心逻辑、受控页面样本、任务状态和 XLS/XLSX 格式的自动化测试。导出文件经独立 Excel 读取库读取，并与用户模板逐列比较。**开发环境无法连接用户的 Chrome，且内置浏览器安全策略阻止访问拼多多，因此尚未完成实际拼多多登录页面的端到端验证。** 实际页面布局、导航方式和访问限制仍需安装后验证。

没有绕过验证码或平台访问限制的功能；遇到这些情况交由用户处理。

## 数据与权限

名称、进度及商品信息保存在 Chrome 本地存储；名称只用于正常拼多多搜索。图片在本地浏览器处理，不上传第三方识图服务，不索取账号密码。

权限用途：`storage` 保存数据、`scripting` 读取各来源页面、`downloads` 保存 Excel、站点权限操作专用采集页并读取站点声明的详情文档。不再下载图片像素用于去重。SheetJS 0.20.3 随插件本地打包，用于生成旧版 `.xls`；运行时不从远端加载代码。

# 历史版本：淘宝翻页与主图识别修复（1.4.1）

- 在结果页底部识别真实“下一页”控件，支持链接、按钮和分页区中的 div/span；翻页后从新列表顶部继续。数量达到设定值立即停止。
- 翻页加载期间等待新列表，不重复点击、不把旧列表或短暂无结果视为结束；等待超时会明确显示翻页失败，保留当前结果。
- 淘宝主图按实际显示尺寸筛选，排除小活动标识并优先读取较大的商品图片；明确售价区域支持“优惠后”“补贴后”“首单价”等尾注和整数售价。优惠券、立减金额不作为售价。
- 进度与结果说明分别显示同图合并、识别跳过及具体分类、已删除同类排除的数量。相似度阈值未更改。旧任务未记录这些统计时不补造数据。
- 更新后在 Chrome 扩展管理页重新加载插件，再对旧失败名称点击“重新搜索”。此前误选主图的旧结果不会自动重算。
- 本版本用本地受控样本验证；实际淘宝页面仍需试采，未宣称实站已通过。
# 历史版本：淘宝未加载字段重读（1.4.2）

1.4.1 在首次看到商品链接时即判定主图或价格缺失，并将 ID 永久标记为已处理。1.4.2 对不完整的淘宝商品先滚动到可见位置，再最多重读 12 次，每次间隔 500ms；仍缺失才计入跳过。图片兼容 data-ks-lazyload/data-lazyload/srcset；售价区域中的尾随付款人数不再影响已明确标出的售价。

# 历史版本：ID 去重与详情图片（1.5.0）

上述历史版本的图片去重、图片授权及缺主图跳过规则已取消。淘宝等待重读只针对名称和价格；连续五条重读仍失败的保护只检查这些字段及商品变化。搜索图片不再是收集条件，详情相册第一张有效图片用于展示和导出。没有图片时保留商品链接并标明原因，其他实际详情和 SKU 字段仍按模板导出。详情被登录或验证码阻断时仍需在详情页处理后继续。

更新后关闭旧管理页和采集页，在 Chrome 扩展页刷新插件并确认版本为 1.5.0，再打开管理页对旧失败名称点击“重新搜索”。旧版本已合并或跳过的商品不会自动恢复，需要重搜。此版本使用受控样本验证，仍未宣称实际淘宝页面已经验证通过。

# 历史版本：图文详情修复（1.5.1）

淘宝和天猫会自动打开“图文详情”，分段滚动并等待图片稳定，读取延迟加载的图片及描述 iframe。已经读到一张图片时仍等待后续内容；详情未读到时保留链接并标记部分信息。

1688 区分导航标签和商品详情正文，排除评价、推荐区和无关 iframe；详情图片过滤已确认的牛头占位图、买家评价图片及网站统计资源。店铺放在商品描述里的活动图片正常保留，不因多个商品共用就删除。

关闭旧管理页和采集页，在 Chrome 扩展管理页刷新插件，确认版本为 1.5.1，再打开管理页点击“重新搜索”。已有结果不会自动清洗，需重新采集后导出。修复用本地受控页面和用户导出文件定位验证，真实淘宝和 1688 页面未直接验证。

# 当前版本：详情只保留图片（1.5.2）

淘宝和天猫以实际详情图片判断加载进度，排除搜索导航、商品页面大容器中的文字与主图；支持延迟加载的 srcset 图片，继续滚动更长的详情区域。没有读到图片时显示“未读到图文详情图片”，保留其他已采集信息。

关闭旧管理页和采集页，在 Chrome 扩展管理页刷新插件并确认版本为 1.5.2。已有结果可直接重新导出去掉文本；补采遗漏的图片需点击“重新搜索”。本地受控样本验证通过，真实淘宝和 1688 页面仍需试采确认。
